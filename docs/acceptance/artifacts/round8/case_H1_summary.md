## TL;DR / 结论（标明置信度）

2026年9月18日，开发者 ferstar 发文揭露智谱旗下 AI 编程工具 ZCode 在用户登录状态下静默将整个工作区（含完整 Git 历史）加密打包上传至阿里云 OSS（置信度：高——多篇独立技术取证与多家媒体报道相互印证）。智谱当晚致歉，称问题源于默认开启的“代码库索引/Repo Wiki”功能，已修复并承诺开源。9月19—20日风波扩大：太原承明科技发函质疑，指出英文版协议显示数据处理主体为智谱注册于新加坡的子公司，质疑数据是否跨境存储（置信度：中——跨境问题目前仅为承明科技单方质疑，智谱未回应，无独立复核）。

## Conclusions

**上传了什么（技术侧，置信度高）**：ferstar 清理磁盘时发现 `~/.zcode/v2/checkpoints` 内一个 313MB 的 `.enc` 加密文件，状态元数据显示为某商业项目（排除 node_modules 后 345MB）的“全量基线快照”，已失败重试 564 次。逆向 Electron 客户端 `app.asar` 后还原上传链路：客户端向 `zcode.z.ai` 申请上传凭证，服务端下发 RSA 公钥与阿里云 OSS 表单签名；本地 tar.gz 打包后用 AES-256-CTR 加密、RSA-OAEP-SHA256 包裹密钥，直传 OSS，OSS 回调注册快照。信封加密的私钥只在 Z.ai 云端，用户连自己磁盘上的密文都解不开。一份 42,411 文件的快照清单显示：`.git/lfs` 196.1MB（56.8%）、`.git/objects` 102.2MB（29.6%）、`.git/logs`（reflog）0.6MB，`.git` 合计占 86.6%，源码与文档仅 13.4%。附加清单还包含全局配置（`mcp.json`、`settings.behavior.json`，常含服务令牌）及触发快照的 prompt 原文。UI 中的开关经代码比对均不控制本地打包上传；删除归档后约半小时即重新打包。

**是否跨境（置信度低，单方质疑）**：上传目的地是阿里云 OSS（存储节点地域未见披露）；但承明科技指出 ZCode 网络请求指向 `zcode.z.ai` / `cdn-zcode.z.ai`，而 Z.AI 英文版平台的缔约主体与个人数据控制者为注册于新加坡的 JINGSHENG HENGXING TECHNOLOGY PTE.LTD，隐私政策载明“服务通常自新加坡提供、个人数据通常在新加坡处理”；中文版协议与隐私政策则写明主体为北京智谱华章，且承诺境内个人信息存储于境内、不跨境传输。承明科技要求智谱说明是否存在跨境传输或境外存储，智谱暂未回应。此问题截至现有证据**无法定论**。

**官方回应**：9月18日下午，智谱在 ZCode 用户群致歉：问题源于“代码库索引”功能（支持会话检查点恢复、历史回退及 Repo Wiki），Repo Wiki 生成页面时可能触发仓库数据上传；该功能上线初期默认开启；Wiki 页面云端生成后上传数据“立即销毁，不会保存”；问题已修复。补偿措施包括近期开源 ZCode、引入第三方评估、全体用户一次额外周额度重置。9月19日发布 3.14.0 版本，更新日志称“修复仓库百科异常上传的问题”。
